4. Bigger refactors this audit surfaced¶

  • Move the 2D interaction diagram out of docking/. A contact map can be computed for any complex, not just a docking pose. Target shape: one pure function (complex in -> interaction JSON out), called from three places: (1) inside the docking chunk via the "Render 2D interaction diagrams" checkbox (engines.py:701), (2) on the fly for a single pose from Results (workspace.py:1113), (3) as a standalone job over a selected set (filter down to 100 ligands -> compute for all). Path (3) is what DockingAPI.compute_diagrams + DiagramJobSpec are today, and they are the ones nobody calls -- they stay, but move to a complex-level home (amdock/complexes/) and take a molecule/complex scope instead of docking result ids. Split the concerns while moving: the interaction JSON is the artifact, the PNG/SVG render is a separate, optional step.
  • ~~Settings: one place to install external tools.~~ DONE 2026-08-30. New amdock/external_tools.py (registry: status / install Steps / uninstall for p2rank, openbabel, pkasso) + amdock/ui/settings_tools.py (ExternalToolsPage), hosted as a Settings tab through a new 5-line AppSettingsPanel.add_page() in ms_components. Installs are blocking modals (run_steps_dialog(..., blocking=True), QThread + streamed log): a job submitted against a half-installed tool costs more than the wait. pocket_detection.py and build.py lost their embedded installers and now only show status + "Install it from Settings > External tools" (MainWindow.open_settings() is the hook). Removal is per tool, with confirmation.
  • Scope staleness policy. A scope is a live query, not a frozen set: a job can be queued with a scope that later yields nothing (molecules deleted, filters that match zero rows). Needs a single check point that turns "empty/stale scope" into a clean, explicit job failure instead of a job that quietly does nothing. Cheap: validate at submit (count > 0) and re-check at chunk build.

  • ~~MAX_2D_PREVIEW_HEAVY_ATOMS: delete the flat app-settings layer.~~ DONE 2026-08-30. The value lives at molecule_display.max_2d_preview_heavy_atoms in the amdockvs configuration source, and AppSettingsPanel._build_tab renders every field of every source generically -- so it is already editable in Settings. What is redundant is the first-generation flat API on top of it: app_setting_specs / get_app_setting / update_app_setting (each a single-key if key != X: raise KeyError) plus AMDOCKVS_APP_SETTINGS/AppSettingSpec in configuration.py:178 and manifest.py:21 (nothing reads manifest.settings). Change: ui/catalog/common.py:192 reads runtime.amdock_configuration.get_value( MAX_2D_PREVIEW_HEAVY_ATOMS_PATH), drop the rest (~35 ln). Keep the legacy-value migration at runtime.py:110.

  • Export the ms_table scope instead of materializing ids. scope_panel.py:171,213, pocket_detection.py:709 and build.py:502 call table.all_filtered_ids() and pass {"id__in": [...]}. MoleculeScope/scope_payload() is already the exportable format and ms_table already exposes active_filters() -> list[FilterSpec]; what is missing is the FilterSpec[] → MoleculeScope.filters translation. The workflow type gate (_entity_filters_for_workflow) is orthogonal and stays.

  • ~~p2rank: drop conda for Java.~~ DONE 2026-08-30. ensure_java17() runs conda install -p <own prefix> openjdk=17, which is why _PROTECTED_CONDA_PACKAGES and the base-env guard exist. Measured alternatives: micromamba binary 18 MB + an openjdk=17 env ~180-330 MB, versus jdk4py at 35 MB (a jlink-trimmed JDK shipped as a plain wheel — uv-installable, wheels for linux x86_64/aarch64, macOS x86_64/arm64 and win_amd64; 17.x, 21.x and 25.x lines available, pin ~=21.0). Change: ensure_java17 + conda_java17_install_plan + _find_conda_command + _PROTECTED_CONDA_PACKAGES (~110 ln) are gone and find_java_command() tries jdk4py.JAVA first. The tarball download/sha256/extract path is untouched.

Test run: pip install jdk4py~=21.0 into MSDD_312 -> JDK 21.0.8, 105 MB unpacked (35 MB wheel). prank predict -f test_data/1fbl.pdb with JAVA_HOME=jdk4py.JAVA_HOME finished successfully in 4.7 s, 4 pockets, and wrote *_predictions.csv + *_residues.csv + visualizations -- so the jlink module set covers p2rank (including java.desktop for the visualizer). For comparison, the P2Rank distribution itself is 293 MB on disk once extracted.

Packaging: [project.optional-dependencies] pockets = ["jdk4py~=21.0"], folded into all. This works only because the JDK is a wheel; tools that genuinely need a conda env (openbabel, pkasso, and later pdb2pqr/openmm) cannot be pip extras, which is why the Settings page installs them instead.
